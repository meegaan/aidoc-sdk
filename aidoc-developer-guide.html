1. Design Philosophy & Core Guarantees

aidoc-sdk is an infrastructure-grade Python SDK designed to transform unstructured documents into a deterministic, canonical JSON representation suitable for AI systems, enterprise pipelines, auditing, and integrity verification. Its primary value proposition rests on five pillars:

1.1 The Five Pillars

Pillar What It Means Consequence of Violation
Determinism Identical input always produces identical output. No randomness, no timestamps in structure, no locale dependencies. MAJOR SDK version bump required
Immutability All Pydantic models are frozen. Every stage returns a new instance — nothing is mutated in place. Runtime error (Pydantic ValidationError)
Structural Integrity Semantic enrichment can ONLY add metadata to block.semantic and processor.semantic_layers. Structure (IDs, text, order) is locked after canonicalization. StructuralViolationError raised by guardrails
Controlled Public Surface Only types/functions listed in __all__ are stable public API. Internal modules may change without notice. N/A (breaking internal change is MINOR)
No Global State Side Effects No global logging configuration. NullHandler attached — caller controls logging. Registries use threading locks. Library behavior does not surprise host application

1.2 Versioning Contracts

⚠ Breaking Change Policy Any change to normalization rules, hashing algorithm, serialization format, or canonical model schema requires a MAJOR SDK version bump, a SPEC_VERSION bump, and a CORE_CONTRACT_VERSION bump.
Constant Current Value Controls When It Bumps
SPEC_VERSION "aidoc@1.0" aidoc-sdk.spec field — embedded in every document Any structural model change
CORE_CONTRACT_VERSION "1.0" processor.aidoc_core field in metadata Normalization, hashing, serialization or fingerprint change
__version__ "1.0.0" Package/pip version Any release

                    ▼
              Final AIDoc ✓

2.3 The Deterministic Core Boundary

The following modules form the deterministic core contract. Any behavioral change requires a MAJOR version bump:

Module Role Change Impact
core/normalizer.py 7-step text normalization (NFKC→whitespace) All existing document hashes become invalid
core/hashing.py SHA-256 hashing with strict UTF-8 All IDs and source_hash values change
core/canonical.py RawDocument → aidoc-sdk transformation Structural identity changes
core/models.py Frozen Pydantic schema (AIDoc, Section, Block) Structural contract breaks
core/serializer.py Canonical JSON (sorted keys, no whitespace, null-strip) All fingerprints change
core/fingerprints.py structural_fingerprint / full_document_fingerprint Integrity checks fail across versions
core/version.py SPEC_VERSION, CORE_CONTRACT_VERSION constants Compatibility policy anchor

6. Core Layer — Processing Internals

6.1 Text Normalization Pipeline

  1. Unicode NFKC normalization
  2. Conversion to str (if not already)
  3. Whitespace collapse (tabs, newlines within paragraphs converted to space)
  4. Trimming leading/trailing whitespace

6.2 Hashing & Canonicalization

SHA-256 is used exclusively. The source_hash is derived from raw input bytes. Block IDs are derived from the SHA-256 hash of their canonical JSON representation (without the ID field).

8. Pipeline Layer

The pipeline architecture dictates a unidirectional flow through discrete stages. Each stage receives a PipelineContext and returns a new (or mutated, non-frozen parts only) context.

8.1 Pipeline Context

class PipelineContext:
    raw_document: RawDocument
    source_hash: str
    extractor_info: ExtractorInfo
    canonical_document: AIDoc | None = None

8.2 Standard Stages

  • CanonicalStage: Canonicalizes raw_document producing canonical_document.
  • MetadataStage: Injects ProcessorInfo based on the extractor identity and core version.
  • SemanticStage: If enabled, passes the document to SemanticProcessor to run configured Semantic Engines.

9. Semantic Layer

Semantic enrichment is fully opt-in and operates solely on the semantic field of blocks.

9.1 SemanticEngine Contract

class SemanticEngine(ABC):
    name: str      # Required - must match @engine decorator
    version: str   # Required - enforced at class definition

    @abstractmethod
    def process(self, document: AIDoc) -> AIDoc: ...

    async def process_async(self, document: AIDoc) -> AIDoc:
        return self.process(document)  # default delegates to sync

9.2 SemanticProcessor & Guardrails

Engines are NOT invoked directly. They are invoked through SemanticProcessor, which acts as a sandbox that enforces structural guarantees after every engine call:

assert_same_spec(before, after)
assert_same_source_hash(before, after)
assert_structure_unchanged(before, after)

If any guardrail fails, a StructuralViolationError is raised and wrapped as an EngineExecutionError.

Failure handling is configurable via PipelineConfig.semantic_fail_fast:

  • semantic_fail_fast=True (default) — Raises EngineExecutionError immediately on any failure.
  • semantic_fail_fast=False — Logs the error, records it in meta.processor.semantic_layers[].error, and continues with remaining engines.

The SemanticLayerInfo model records each engine's name, version, status ("success" or "failed"), and optional error message for full auditability.

9.4 Implementing a Custom BaseLLMClient

To connect the LLMEngine to a specific provider (OpenAI, Anthropic, or internal API), implement the BaseLLMClient interface. This keeps the semantic logic agnostic of transport details.

from aidoc-sdk.semantic.llm.client import BaseLLMClient

class MyCustomClient(BaseLLMClient):
    name = "my_custom_adapter"

    async def generate(self, prompt: str) -> Dict[str, Any]:
        # 1. Wrap prompt for your specific provider
        # 2. Call provider API (await)
        # 3. Return parsed JSON dict
        return {"requirements": [...]}

9.5 Semantic Engine Extensibility (Domain Engines)

Domain-specific semantic enrichers (e.g., Legal, Finance, Healthcare) can be distributed as independent packages without modifying the Core SDK. They use the public decorator to register themselves automatically. 

# Example: aidoc_legal/engine.py
from aidoc-sdk.semantic.decorators import engine
from aidoc-sdk.semantic.base import SemanticEngine

@engine("legal_analyzer")
class LegalEngine(SemanticEngine):
    name = "legal_analyzer"
    version = "1.0"

    def enrich(self, document):
        # ... implementation ...
        return document.model_copy()

In the consuming application, importing the module executes the decorator, allowing it to be added to the pipeline:

import aidoc_legal  # Triggers @engine registration
        
config = PipelineConfig(enable_semantic=True, semantic_engines=["legal_analyzer"])

12. Version Governance & Compatibility

aidoc-sdk adheres strictly to Semantic Versioning 2.0.0 for its package constraints.

  • MAJOR: Processing internals, normalization rules, schema breaking changes, API rewrites.
  • MINOR: New extractors, new pipelines stages, new built-in engines, optional fields.
  • PATCH: Bug fixes, security fixes, dependency bumps transparent to user.
Continuous Verification All CI builds run regression fingerprint tests against golden JSON fixtures to ensure cross-version determinism.

13. Advanced Patterns

13.1 Async Safety

Pitfall: Calling pipeline.run() in async contexts Use await pipeline.run_async() inside async tasks/handlers. Async-only stages raise NotImplementedError on the sync path - this prevents silent hangs! Never use asyncio.run() inside a stage or engine.

13.2 Multi-Engine Pipelines

@engine("compliance_check")
class ComplianceEngine(SemanticEngine): ...

config = PipelineConfig(
    enable_semantic=True,
    semantic_engines=["rule_engine", "compliance_check"] # Executes sequentially
)

15. Glossary

  • AIDoc: The root canonical entity containing metadata, processing info, and sections.
  • Canonicalization: The strict process of parsing raw structures into cryptographically identical nodes.
  • Fingerprint: SHA-256 string representing the identity of a block or document.
  • Guardrails: Diff-check assertions ensuring engines do not alter immutable structure bounds.
  • Semantic Object: Inferred meaning (e.g., Requirement, Prohibition) layered on top of canonical text blocks.
